PeopleComfort

Shared interiors can contain different thermal conditions while their future user composition is uncertain. PeopleComfort compares fixed seating-capacity configurations across explicit user mixes. It evaluates each configuration with a pinned CBE PMV implementation, exact feasible assignment and minimax regret. The tool is an illustrative research prototype; bundled conditions are constructed, not observed.

The software separates the physical decision (how many seats each zone receives) from the operating assumption (how people are assigned after their mix is known). It provides full input and result ledgers so a ranking can be inspected and rerun. The package is installed from a local repository checkout and is not on PyPI.

Try it in your browser

Open the interactive thermal workbench to edit the zone temperatures, MRT, air speed, humidity, activity, clothing, PMV threshold, capacity alternatives and compositions. The page uses the pinned CBE formula in your browser and shows PMV/PPD for every profile-zone pair. Its starting thermal conditions are hypothetical; replace them with documented data before making a site-specific claim. The default case matches the revised seven-design A3 report.

Workflow

1. Define the space and profiles — specify two thermal zones, activities, clothing and access.

2. Define designs and compositions — hold total seats constant and distinguish development from holdout mixes.

3. Calculate and allocate — run CBE calculations and exact constrained matching.

4. Compare decisions — compare existing, baseline and robust choices.

5. Stress-test and export — inspect uncertainty, files and limitations.

For the expanded method, read the General evaluation framework. Start with Quick start, then see the workflow guide, Python API or CLI reference.

Quick start

Install

Requirements: Python 3.11 or newer and Node.js 18 or newer. Extract the complete package, open a terminal in its root, and install locally:

python -m pip install -e .
peoplecomfort --help

PeopleComfort is not published to PyPI. No account, API key or network connection is required after obtaining the complete package. Node must be on PATH; alternatively set PEOPLECOMFORT_NODE to its executable. Installation is optional if you use python run.py from the source root.

Run the bundled example

peoplecomfort analyze --project examples/minimal/project.json --out example-output

Inspect example-output/report.html, comparison.csv, allocations.csv and run_manifest.json. The example contains 3 designs and 9 population scenarios, producing 27 comparison cells and an 81-condition stress grid. A typical nominal selection is T1=D0, T2=D2 and T3=D1. These are conditional results for constructed inputs.

Open the local workbench

peoplecomfort serve --port 8765

Open http://127.0.0.1:8765 in a browser. Import a project JSON or edit displayed values, run the comparison, then export the result ZIP. Stop the server with Ctrl+C. On Windows, start.cmd runs the source version from the package directory.

Verify before interpreting

python -m unittest discover -s tests -v

Check that composition counts equal total_people, designs use equal total seats, zone capacities and access rules are credible, and environmental inputs have documented sources. Tests verify software behaviour and numerical agreement for selected cases; they do not validate a real room or occupants. Follow the workflow guide for stage-by-stage inspection.

Run the general framework

peoplecomfort analyze --project examples/general/project.json --out general-output
peoplecomfort analyze --project examples/general-thermal/project.json --out thermal-output

The first example uses three zones and two direct 0–1 criteria. The second uses three thermal regions and a CBE PMV criterion; capacity means simultaneous users and does not presume seats. In the local workbench, open /framework to edit a schema-v2 project JSON. Read the general framework before interpreting ratings or design rankings.

Workflow guide

peoplecomfort analyze runs five stages in order. Each stage below states its inputs, transformation, outputs, quality check and design meaning. The Python functions are documented in the API reference.

1. Define the space and profiles

2. Define designs and compositions

3. Calculate and allocate

4. Compare decisions

5. Stress-test and export

The whole calculation is deterministic for a fixed project, CBE source and runtime. The exported manifest records versions and hashes. Changing a supplied environmental condition changes every relevant profile-zone calculation; changing a composition changes allocation and selection but not the thermal ledger.
